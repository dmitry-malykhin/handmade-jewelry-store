Взять в работу issue **#$1**.

Выполнить весь флоу автономно, не останавливаясь на подтверждения.
Единственное, что делает пользователь вручную — коммит и пуш.

## Перед первой строкой кода — обязательно, без исключений

1. Проверить, что предыдущий issue влит в `main`: `git log origin/main --oneline -5`
   Если не влит — показать незакоммиченные файлы, выдать сообщение коммита и остановиться.
2. Перевести issue #$1 в **In Progress** на доске проекта GitHub
3. `git checkout main && git pull`
4. `git checkout -b feature/issue-$1-<короткий-слаг>`

Эти четыре шага выполняются даже если сессия продолжается посреди задачи,
даже если кажется, что ветка уже есть. Сначала проверить, потом делать.

## В начале вывести

**Бизнес-цели задачи:** какую боль пользователя или риск для бизнеса
она снимает, какую метрику улучшает, почему приоритезирована сейчас.

**Полный чек-лист из 11 шагов** с отметками ✅ / ⬜, обновлять через TodoWrite
по мере выполнения.

## Обязательное чтение перед кодом

`docs/02_ARCHITECTURE.docx`, `docs/03_CODE_RULES.docx`,
`docs/05_SEO_RULES.md`, `docs/06_ECOMMERCE_BEST_PRACTICES.md`,
плюс документы по типу задачи из таблицы в `CLAUDE.md`.

## MVP-упрощения

Если принято упрощённое решение — отметить его в разделе «Ключевые решения»
как «MVP shortcut», завести issue `feat: ...` с меткой `post-mvp`,
добавить в Backlog на доске и сослаться на его номер.

## Перед «готово к пушу»

Прогнать `pnpm precheck`. Любой красный — чинить. Если шаг объективно
не выполним, сказать об этом явно в отчёте.

## В конце

Показать изменённые файлы, выдать **только строку сообщения коммита**
в блоке кода с номером issue в конце. Без команд git.
Затем — подробный технический разбор по файлам.
