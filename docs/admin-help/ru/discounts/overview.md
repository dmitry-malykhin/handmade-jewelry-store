# Промокоды

## Зачем эта страница

Коды скидок, которые покупатель вводит на чекауте чтобы снизить сумму
заказа. Два типа: процент (`10% скидка`) или фиксированная сумма
(`$5 скидка`).

Используй страницу чтобы:

- Создавать коды под кампании (`WELCOME10`, `SUMMER25`, `BFCM30`)
- Включать / отключать коды (toggle)
- Смотреть статистику использования
- Soft-delete кодов, которые больше не должны работать

## Поля и элементы управления

### Код
- **Зачем**: Строка, которую покупатель печатает в поле промокода на
  чекауте.
- **Как заполнять**: 3–30 знаков: `A-Z 0-9 дефис подчёркивание`.
  Регистр на чекауте не важен (`welcome10` работает для `WELCOME10`).
- **Эффект**: Идентификатор для покупателей. После рассылки считай
  неизменяемым.
- **Рекомендация**: ALL_CAPS, коротко, запоминаемо.
  `WELCOME10`, `THANKS5`, `VIP15`.

### Тип
- **Зачем**: Как считается скидка.
- **Значения**:
  - `% скидка` — `Значение` это процент (1–100)
  - `Фикс. скидка` — `Значение` это центы (например `500` = $5.00)

### Значение
- **Зачем**: Величина скидки.
- **Как заполнять**:
  - Для `% скидка`: целое 1–100 (валидация в форме)
  - Для `Фикс. скидка`: в центах (`500` = $5)
- **Эффект**: Ограничено суммой заказа на чекауте — в минус не уйдёт.
- **Рекомендация**: 10–15% для кодов первой покупки; $5–10 фикс для
  лояльных.

### Мин. сумма заказа (центы)
- **Зачем**: Код работает только если `subtotalCents >= minOrderCents`.
- **Как заполнять**: В центах (`5000` = $50).
- **Эффект**: Не даёт сжечь 10% код на $10 заказ.
- **Рекомендация**: 3–5x величины скидки (для 10%-кода — минимум $50).

### Макс. использований (необязательно)
- **Зачем**: Общий cap на использования. После N успешных чекаутов код
  перестаёт работать для всех.
- **Как заполнять**: Целое ≥ 1 или оставить пустым (без лимита).
- **Эффект**: Полезно для limited-time акций и инфлюенсер-кодов.

### Дата истечения (необязательно)
- **Зачем**: Дата после которой код недействителен.
- **Как заполнять**: Date picker. UTC полночь.
- **Эффект**: После даты код возвращает «истёк» на чекауте.

### Toggle активности (по строке)
- **Зачем**: Временно отключить без удаления.
- **Эффект**: Неактивные коды возвращают «недействителен» на чекауте.
  Включить обратно — toggle назад.

### Действие удаления (по строке)
- **Зачем**: Soft-delete — выставляет `deletedAt`, убирает код из
  списка, но сохраняет историю заказов где он был применён.
- **Эффект**: История остаётся целой (видна применённая скидка по
  старым заказам). Код больше не используется. Откатить через UI
  нельзя — только через БД.

## Типичные сценарии

**Welcome-оффер для подписчиков**
Код: `WELCOME10` | тип `% скидка` | значение `10` | мин. сумма `5000`
($50) | без истечения | без max использований. Активен.

**Чёрная пятница — 30% скидка, первые 100 покупателей**
Код: `BFCM30` | `% скидка` 30 | мин. сумма `0` | max использований `100`
| истекает 30 ноября. Активен.

**Коллаба с инфлюенсером — $20 скидка на любой заказ, 500 использований**
Код: `JANE20` | `Фикс. скидка` 2000 | мин. сумма `0` | max использований
`500` | истекает через 3 месяца. Активен.

## Подводные камни

- **Процент > 100 отклоняется** формой (клиент + сервер).
- **Отрицательная сумма заказа = 0** — `$50 скидка` на $30 заказ делает
  заказ бесплатным, в минус не уйдёт.
- **Коды case-insensitive на чекауте** но хранятся как ввёл. ALL_CAPS
  для читаемости.
- **Soft-delete сохраняет историю.** Удалённый код виден в строке
  «применённая скидка» старого заказа.
- **Интеграция чекаута отложена** — эта страница позволяет управлять
  кодами, но их применение на чекауте — отдельная задача в backlog.
  До этого момента коды реально не снизят сумму у покупателя.
- **Per-customer лимит отсутствует** — один и тот же клиент может
  применить код много раз, пока не сработает max использований.
