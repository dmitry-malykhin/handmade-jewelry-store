# Детали заказа

## Зачем эта страница

Рабочее место по одному заказу. Здесь — всё что нужно чтобы исполнить,
отследить, вернуть деньги или разобраться по конкретной покупке.

Структура страницы сверху вниз:

1. **Сводка заказа** — ID, суммы, источник, статус оплаты
2. **Покупатель** — email + тип (гость / зарегистрирован)
3. **Позиции заказа** — что отправляется
4. **Адрес доставки**
5. **Статус заказа** — кнопки переходов по state machine
6. **Трекинг** — форма перевозчик + трек-номер
7. **Кнопка возврата** — открывает модалку (только если оплата `SUCCEEDED` или `PARTIALLY_REFUNDED`)
8. **История статусов** — каждое изменение со временем и автором

## Поля и элементы управления

### Кнопки «Сменить на …»
- **Зачем**: Один клик на каждый разрешённый переход вперёд.
- **Эффект**: Моментальная запись. Добавляется запись в историю. При
  переходе в `Доставлен` начисляются лояльные баллы и отправляется
  email подтверждения.
- **Рекомендуемый порядок**: Оплачен → В обработке (когда начал работу)
  → Отправлен (после сохранения трекинга) → Доставлен (после
  подтверждения от покупателя).

### Трекинг — Перевозчик
- **Зачем**: Кто доставляет посылку.
- **Как заполнять**: Выбор из `USPS / FedEx / UPS / DHL`.
- **Эффект**: Показывается покупателю в email и личном кабинете.

### Трекинг — Трек-номер
- **Зачем**: ID отправления от перевозчика.
- **Как заполнять**: Скопируй точно как на этикетке. Без пробелов.
- **Эффект**: При сохранении статус заказа автоматически становится
  `Отправлен` (если ещё не был), покупателю уходит email «ваш заказ
  отправлен».
- **Edge case**: Сохранение трекинга на уже отправленном заказе
  обновляет номер без повторной отправки email — полезно при опечатке.

### Этикетка доставки (EasyPost)
- **Зачем**: Купить настоящую этикетку перевозчика, не уходя из заказа.
- **Когда видна**: Только на заказах в статусе `PAID` или `PROCESSING`,
  у которых ещё нет этикетки. После покупки форма меняется на ссылку
  «Скачать PDF этикетки».
- **Бейдж режима**: `Dry run` — `EASYPOST_API_KEY` не настроен, система
  возвращает фейковый URL и трек-номер, чтобы прокатать UI. `Live` —
  следующий клик стоит реальных денег. Всегда смотри на бейдж.
- **Перевозчик**: Те же 4 опции, что и в ручном трекинге. Выбранный
  здесь перевозчик автоматически записывается в заказ.
- **Тумблер страховки**: Появляется только при сумме заказа ≥ $100.
  Включён — посылка страхуется на сумму заказа. Частичной страховки
  в UI нет; нужна особая сумма — заходи в портал перевозчика напрямую.
- **Последствия**: Один клик пишет в заказ shipment id, tracker id,
  трек-номер, URL этикетки и сумму страховки. Статус **не** двигается
  в `SHIPPED` — сначала отнеси посылку, потом руками подними статус.
  Когда перевозчик отметит доставку — webhook EasyPost автоматически
  переведёт заказ в `DELIVERED` (с начислением баллов и письмом).

### Кнопка «Оформить возврат»
- **Зачем**: Полный или частичный возврат через Stripe.
- **Когда видна**: Только когда `payment.status` = `SUCCEEDED` или
  `PARTIALLY_REFUNDED`. Скрыта для полностью возвращённых и неоплаченных.
- **Как заполнять**: В модалке — оставь сумму пустой для полного
  возврата, всегда выбери причину, добавь комментарий для архива.
- **Эффект**: Вызов Stripe `refunds.create`, обновление статуса заказа,
  email покупателю, запись в [журнале возвратов](refunds.md).

## Типичные сценарии

**Стандартное исполнение**
Пришёл оплаченный заказ → отправь → сохрани трекинг → статус автоматом
становится Отправлен → когда покупатель подтвердит или пройдёт срок
доставки, переведи в Доставлен.

**Покупатель хочет частичный возврат (например серьга пришла повреждённой на $200 заказ)**
Клик **Оформить возврат** → сумма `30.00` → причина `Товар повреждён`
→ комментарий «левая серьга погнута, возврат стоимости одной». Submit.
Заказ переходит в `Частичный возврат`.

**Неверный трек-номер**
Просто сохрани правильный. Откат статуса не нужен.

## Подводные камни

- **Источник** показывает откуда заказ (`web`, `pos`, …). Пусто (`—`)
  для старых заказов до запуска tracking-а.
- **`кем` в истории** — email админа, сделавшего переход. Stripe webhook
  показан как `system`.
- **Кнопка возврата исчезает после полного возврата** — статус становится
  `Возврат`, возвращать больше нечего. Запись сохраняется для аудита.
- **State machine односторонний**: после `Возврат` или `Доставлен` назад
  нельзя. Лояльные баллы при `Доставлен` откатываются только через возврат.
