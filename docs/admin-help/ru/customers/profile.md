# Профиль клиента

## Зачем эта страница

Глубокий вид по одному зарегистрированному клиенту. Метаданные, все
заказы, все адреса доставки.

Только для чтения. Админ **не редактирует данные клиента** — клиенты
сами управляют своим email, паролем и адресами через витрину.
Это намеренно: правки PII должны быть auditable и не должны быть
одним кликом.

## Разделы

### Карточка профиля
- **Email** — логин-email
- **Зарегистрирован** — дата создания аккаунта
- **Всего заказов** — все статусы
- **LTV** — оплаченные USD минус возвраты (та же формула что в списке)

### История заказов
Каждый заказ клиента, новые сверху. Клик на ID → детали заказа.
Badge статуса показывает текущий статус заказа.

### Сохранённые адреса
Все адреса доставки, сохранённые в аккаунте. Помеченный **По умолчанию**
автоподставляется на чекауте.

## Типичные сценарии

**Поддержка по телефону**
«Хочу узнать про заказ ABC123 на прошлой неделе» → поиск по email в
[Клиенты](overview.md) → открой профиль → клик на заказ в истории →
страница деталей с полным контекстом.

**Аудит качества адресов**
Несколько опечаток в **Адресах** → запиши ID клиента → проверь
коррелируют ли проблемы с доставкой с его LTV перед ручным обращением.

**Проверка истории возвратов**
В истории заказов статусы выделены — `Возврат` и `Частичный возврат`
сразу видны. Клик в детали → причина возврата и история.

## Подводные камни

- **Кнопок редактирования нет специально** — админ не меняет PII через
  админку. Клиент сам через витрину.
- **Кнопки «Удалить клиента» нет.** Удаление аккаунта — GDPR-sensitive
  процесс, идёт через документированный support flow (escalate email-ом).
- **`По умолчанию` адрес — один на клиента.** Адресов может быть
  несколько, но default только один.
- **Профиля гостя нет** — у гостей нет аккаунта. Их заказы доступны
  только через страницу [Заказы](../orders/overview.md).
