# Редактирование товара

## Зачем эта форма

Изменение существующей карточки товара. Все поля те же, что и в
[Создании товара](create.md) — разница в эффектах:

- **Изменения сохраняются на лету** при нажатии **Сохранить изменения**
- **Кэш ISR на каталоге = 1 час** — некоторые правки видны покупателям с
  задержкой; страница самого товара ревалидируется чаще
- **Изменение статуса** доступно прямо из таблицы товаров (не нужно
  заходить в редактор)

## Что особенно осторожно менять

### URL-слаг
- **Зачем**: Часть URL товара.
- **Эффект изменения**: **Все внешние ссылки сломаются** — Google
  Shopping feed, Pinterest pins, Facebook ads.
- **Рекомендация**: Не меняй после публикации. Если без этого никак —
  добавь redirect в `next.config.js`.

### Цена
- **Эффект**: Цена применяется ко всем будущим заказам. Существующие
  заказы и корзины используют цену, зафиксированную на момент добавления.
- **Рекомендация**: Меняй сразу для всех вариантов или по плану акции.

### Тип наличия
- **Эффект**: Смена с **В наличии** на **Под заказ** немедленно меняет
  поведение оформления заказа. Установи **Дней производства**, иначе
  покупатель не увидит ожидаемый срок.
- **Рекомендация**: При переходе в **Единственный экземпляр** —
  убедись что остаток = 1 (форсируется системой).

### Количество на складе
- **Зачем**: Быстро обновить остаток.
- **Альтернатива**: Используй [Склад](inventory.md) для inline-edit
  без захода в форму.

### Изображения
- **Эффект**: Удаление главного фото (первого в списке) — новое главное
  определяется автоматически.
- **Рекомендация**: Не удаляй фото массово — лучше добавь новые и
  переставь порядок drag-and-drop.

## Типичные сценарии

**Снять фото плохого качества и добавить новое**
Открой форму → в разделе **Изображения** удали проблемное фото →
загрузи новое → **Сохранить изменения**.

**Поднять цену перед сезоном**
Открой форму → **Цена** → новое значение → **Сохранить**. Все будущие
заказы по новой цене; существующие корзины используют старую цену.

**Опечатка в описании**
Открой форму → **Описание** → правка → **Сохранить**. На странице
товара изменение видно сразу.

## Подводные камни

- **Изменения цены задним числом не пересчитывают существующие заказы**
  — это правильно (бухгалтерский snapshot цены на момент покупки).
- **При смене типа на «Под заказ» обязательно заполни «Дней производства»**
  — без этого появится валидационная ошибка.
- **Удалять товар можно только если на него никогда не было заказов** —
  иначе используй **Архив** (статус).
